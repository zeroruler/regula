# DESIGN.md — Terrazzo 디자인 시스템

1981년 밀라노 멤피스 그룹의 언어를 화면으로 옮긴 시스템. 이 문서의 값만 사용하고, 없는 색상·크기·폰트를 임의로 추가하지 않는다.

**컨셉 한 줄**: 원색 조각을 검은 선으로 오려 붙인 화면. 소란은 여백에 가두고, 글자가 얹히는 면은 흰 종이로 남긴다.

**세 가지 시그니처** — 이 시스템을 다른 시스템과 구별하는 것:
1. **검은 윤곽선과 하드 섀도우** (§4) — 모든 면은 2px 검정 테두리 + 번지지 않는 단색 그림자. 모서리를 굴리지 않는다. 종이를 오려 붙인 것처럼 보여야 한다.
2. **한 블록 한 색** (§2) — 카드·섹션마다 팔레트에서 색을 하나씩만 가져간다. 그 블록 안은 검정과 흰색뿐이다. 색이 많아도 싸우지 않는 이유가 이것이다.
3. **패턴은 여백에만** (§6) — 지그재그·도트·테라조 반점은 배경 레이어 전용. 글자가 얹히는 면에는 절대 깔지 않는다.

**문서 사용법**: §1 토큰을 그대로 복사해 시작 → §2 장식 밀도를 먼저 고르고 → §3~§8 규칙에 따라 조합 → 판단이 애매하면 §9 빠른 결정 규칙.

## 1. Design Tokens (모든 값의 원본 — 여기 외에 값을 정의하지 않는다)

```css
:root {
  /* Structure — 이 시스템의 뼈대는 색이 아니라 검은 선이다 */
  --ink: #151515;                   /* 테두리, 그림자, 제목 */
  --stroke: 2px;                    /* 모든 테두리 두께 — 1px도 3px도 쓰지 않는다 */
  --shadow-sm: 3px 3px 0 var(--ink);   /* 버튼, 뱃지 */
  --shadow: 4px 4px 0 var(--ink);      /* 카드, 입력창 */
  --shadow-lg: 6px 6px 0 var(--ink);   /* 히어로 블록, 모달 */
  --shadow-lift-sm: 6px 6px 0 var(--ink);  /* 버튼 hover — 종이가 뜬다 */
  --shadow-lift: 8px 8px 0 var(--ink);     /* 카드 hover */
  --radius: 0;                      /* 기본값은 각지게 */
  --radius-pill: 9999px;            /* 칩·뱃지만 */

  /* Surface */
  --canvas: #FFFDF7;                /* 페이지 바닥 — 아주 옅은 종이색 */
  --paper: #FFFFFF;                 /* 블록 표면. 글이 얹히는 면은 언제나 이 색 */
  --paper-sunken: #F2EFE7;          /* 스켈레톤, 비활성 */

  /* Text */
  --ink-2: #3A3A3A;                 /* 본문 */
  --ink-3: #6B6B6B;                 /* 보조, 캡션, 플레이스홀더 */

  /* Palette — 6색. 각 색 위에 올리는 글자색은 아래 --on-* 로 고정되어 있다 */
  --red:    #DE2F27;  --on-red:    #FFFFFF;   /* 4.62:1 */
  --yellow: #F5C518;  --on-yellow: #151515;   /* 11.2:1 */
  --blue:   #2B4CE0;  --on-blue:   #FFFFFF;   /* 6.54:1 */

  --green:  #12A05F;  --on-green:  #151515;   /* 5.41:1 */

  /* Semantic — 팔레트에 역할을 지정한 것일 뿐, 새 색이 아니다 */
  --danger:  var(--red);
  --warning: var(--yellow);
  --success: var(--green);
  --info:    var(--blue);

  /* Chart — 사용 순서 고정 */
  --chart-1: #DE2F27; --chart-2: #2B4CE0; --chart-3: #F5C518;
  --chart-4: #17B3B0; --chart-5: #F573A9; --chart-6: #151515;  /* 6번째는 검정 */

  /* z-index — 이 6단계만. 임의 값 금지 */
  --z-pattern: 0;  /* 패턴 레이어는 언제나 콘텐츠 아래 */
  --z-header: 100; --z-dropdown: 200; --z-backdrop: 300;
  --z-modal: 400;  --z-toast: 500;

  /* Typography — 라틴은 앞 폰트가, 한글은 뒤 폰트가 받는다 (§3) */
  --font-display: "Archivo Black", "Black Han Sans", sans-serif;
  --font-sans: "Gothic A1", -apple-system, BlinkMacSystemFont, sans-serif;
  /* 모노는 이 시스템에 없다 — §3 참고 */

  /* Motion — 움직임의 양은 §2 장식 밀도를 따른다 */
  --ease: cubic-bezier(0.2, 0, 0.2, 1);          /* 퇴장, 페이드 — 딱 멈춘다 */

  /* Layout */
  --container: 1160px;  /* 본문 중심 페이지는 720px */
  /* breakpoint: mobile <640px / tablet 640–1024px / desktop ≥1024px */
```

## 2. Color Rules (색 사용 규칙)

### 장식 밀도 — 무엇을 만들든 이것부터 고른다
`<body data-density="...">` 하나로 시스템의 온도를 조절한다. 프로젝트 성격에 맞는 단계를 **먼저 정하고** 나머지를 조합한다.

| 단계 | 쓰는 곳 | 켜지는 것 | 움직임 |
|------|---------|-----------|--------|
| `full` | 랜딩, 이벤트, 포트폴리오 | 패턴 레이어 + 떠다니는 도형 + 색 블록 전부 | 오버슛 + 카드 기울임 + 도형 부유 |
| `half` | 일반 서비스 화면 | 윤곽선·하드 섀도우 + 색 블록. **패턴과 도형 없음** | 오버슛까지만. 기울임·부유 없음 |
| `quiet` | 대시보드, 문서, 긴 폼 | 윤곽선만. 색은 화면에서 강조 1곳 | 최소. 뜸도 없이 눌림만 |

- 밀도를 낮춰도 §1 토큰은 그대로다. 끄는 것은 장식이지 구조가 아니다
- 한 프로젝트 안에서 페이지마다 밀도를 섞지 않는다. 랜딩만 `full`, 나머지 앱 화면은 `half`처럼 **역할이 다르면** 허용

### 색 규칙
1. **한 블록 한 색.** 카드·섹션·배너는 팔레트에서 색을 하나만 가져간다. 그 블록 내부의 텍스트·아이콘·구분선은 검정과 흰색뿐이다
2. **색 위의 글자색은 고르는 것이 아니다.** `--on-red`, `--on-yellow` 처럼 짝이 이미 정해져 있다. 노랑 위에 흰 글씨(1.63:1), 파랑 위에 검은 글씨(2.79:1)는 시스템에서 불가능한 조합이다
3. **팔레트 색을 흰 배경 위 본문 텍스트로 쓰지 않는다.** 노랑·청록·핑크는 흰 배경에서 3:1도 못 넘긴다. 색은 **면**으로 쓰고, 글자는 검정으로 쓴다. 예외는 큰 제목(24px 이상)의 빨강·파랑뿐
4. 인접한 블록에 같은 색을 연속으로 쓰지 않는다. 팔레트 순서대로 돌린다
5. 그라데이션 금지. 멤피스는 단색 면과 패턴으로만 이루어진다
6. 반투명 금지 — 백드롭만 예외(§4). 색은 겹치지 않고 나란히 놓인다
7. 새 텍스트/배경 조합을 만들면 WCAG AA(4.5:1) 확인. §1 조합은 라이트·다크 양쪽에서 검증되었다

## 3. Typography (타이포그래피)

### 두 활자가 한 줄을 나눠 쓴다
`--font-display`는 폰트를 두 개 나열한다. 브라우저가 글자마다 갈라 쓰므로 **영문·숫자는 Archivo Black, 한글은 검은고딕**이 받는다. 순서를 바꾸지 않는다.

### Scale
| 역할 | 폰트 | 크기 | 굵기 | 행간 | 자간 |
|------|------|------|------|------|------|
| Display | display | 64px | 400\* | 1.0 | -0.02em |
| H1 | display | 44px | 400\* | 1.05 | -0.02em |
| H2 | display | 32px | 400\* | 1.15 | -0.01em |
| H3 | sans | 22px | 900 | 1.35 | -0.01em |
| H4 | sans | 18px | 700 | 1.45 | 0 |
| Body Large | sans | 18px | 400 | 1.7 | 0 |
| Body | sans | 16px | 400 | 1.7 | 0 |
| Small | sans | 14px | 400 | 1.6 | 0 |
| Caption | sans | 13px | 700 | 1.5 | 0 |
| Chip | sans | 12px | 900 | 1.2 | 0.12em, 대문자 |
| Metric | display | 40px | 400\* | 1 | -0.02em |
| Button | sans | 15px | 900 | 1 | 0 |

\* 검은고딕과 Archivo Black은 굵기가 하나뿐이다. 제목의 무게는 굵기가 아니라 **크기**로 만든다.

### Rules
- 본문 굵기는 400/700/900만. 검은고딕에 가짜 굵기(`font-weight: bold`로 억지로 굵게)를 걸지 않는다 — 획이 뭉개진다
- 본문 최소 16px, 행간 1.7. 제목이 무거운 만큼 본문은 넉넉히 띄운다
- **제목은 짧게 자른다.** 검은고딕은 획이 두꺼워 세 줄이 넘어가면 검은 덩어리로 보인다. Display·H1은 두 줄까지
- 본문에 검은고딕을 쓰지 않는다. 16px 이하에서는 속공간이 막혀 읽히지 않는다
- 제목 안에서 단어 하나를 팔레트 색으로 강조하는 것은 허용 — 화면당 한 번

### 칩 라벨 규칙 — 이 시스템의 라벨
모노스페이스를 쓰지 않는다. 대신 **검정 칩에 흰 글씨**를 라벨로 쓴다.
- 형태: 배경 `--ink`, 글자 `--paper`, 12px/900/자간 0.12em/대문자, 패딩 4px 10px, radius 0
- 쓰는 곳: 섹션 머리말, 카테고리, 상태 표시, 번호 매기기
- 색 블록 위에 놓을 때만 칩 배경을 흰색 + 검은 글씨로 뒤집는다
- 한 화면에 5개까지

## 4. Components (컴포넌트)

### 모든 면의 공통 규칙
- 테두리 `var(--stroke) solid var(--ink)` — 예외 없음
- 그림자는 §1의 하드 섀도우 3종만. **흐릿한 그림자(`blur`)는 이 시스템에 존재하지 않는다**
- 모서리는 각지게(`--radius: 0`). 칩·뱃지만 pill

| 상태 | 규칙 |
|------|------|
| Hover | **그림자가 커지고 요소가 뜬다** — `--shadow-lift-sm`, `translate(-2px,-3px)`, `--dur-pop` + `--ease-pop`. 밀도 `quiet`에서는 생략 |
| Active | 그림자 `0 0`, `translate(3px, 3px)`, `--dur-fast` — 종이가 완전히 눌러붙는다 |
| Focus | 테두리 바깥에 3px 오프셋 아웃라인 `outline: 3px solid var(--ink); outline-offset: 3px` |
| Disabled | 배경 `--paper-sunken`, 글자 `--ink-3`, 그림자 제거, `cursor: not-allowed` |
| Loading | 글자를 점 3개 애니메이션으로 교체, **폭 유지**, 클릭 잠금 |

### Buttons
공통: 테두리 2px, 그림자 `--shadow-sm`, 15px/900, 높이 Large 52 / Medium 44 / Small 34px, 패딩 0 22px(Medium).

| 종류 | 배경 | 글자 | 용도 |
|------|------|------|------|
| Primary | 그 블록의 색 | 그 색의 `--on-*` | 핵심 동작 |
| Neutral | `--paper` | `--ink` | 일반 동작 |
| Ink | `--ink` | `--paper` | 강한 강조 — 화면당 1개 |
| Quiet | 투명, 테두리 없음, 그림자 없음, 밑줄 | `--ink` | 3순위 |

- Primary 버튼의 색은 **그 버튼이 속한 블록의 색을 따른다**. 버튼만 다른 색을 갖지 않는다 (§2-1)
- 파괴적 동작은 빨강 Primary가 아니라 **Neutral 버튼 + 확인 모달**로 처리한다. 빨강은 이 시스템에서 장식 색이기도 해서 위험 신호로만 읽히지 않는다

### Cards
- `--paper` 배경, 2px 테두리, `--shadow`, 패딩 24px, radius 0
- 색은 **상단 8px 띠** 또는 **카드 전체 배경** 둘 중 하나로만 쓴다. 둘을 동시에 쓰지 않는다
- 클릭 가능한 카드: hover 시 `--shadow-lift` + `translate(-3px,-4px)` — 뜬다
- **밀도 `full`에서만 카드를 −2°/+2°로 번갈아 기울인다**(붙여놓은 스티커처럼). hover 시 0°로 펴진다. 기울인 카드는 모서리가 서로 침범하므로 **간격을 24px에서 32px로 넓힌다**
- 카드 안에 카드를 넣지 않는다 — 테두리가 겹치면 화면이 감옥처럼 보인다

### Inputs
- 높이 44px, `--paper` 배경, 2px 테두리, `--shadow`, 패딩 0 14px, radius 0
- 글자 16px `--ink`, 플레이스홀더 `--ink-3`
- Focus: 오프셋 아웃라인(위 표) / 오류: 테두리 `--red` + 아래 13px/700 `--red` 도움말
- 라벨 필수: 14px/900 `--ink`, 입력창 위 8px

### Chips / Badges
- 칩(라벨): §3 규칙 — 검정 배경 흰 글씨, radius 0
- 뱃지(상태): pill, 2px 테두리, 팔레트 색 배경 + 해당 `--on-*` 글자, 12px/900
- **상태를 색으로만 구분하지 않는다** — 뱃지 안에 항상 단어를 넣는다

### Navigation
- 고정 헤더: `--paper` 배경(반투명 금지), 하단 2px `--ink` 선, 높이 68px
- 링크 15px/700 `--ink-2` → hover/활성 `--ink`. 활성 항목은 **글자 뒤에 색 블록**을 깐다(형광펜처럼), 밑줄이 아니라
- 우측 Primary 버튼 1개
- 모바일: 햄버거 → 전체 화면 드로어, 배경은 팔레트 색 하나로 꽉 채운다

### Modals / Dropdowns / Toast
| 요소 | 스타일 |
|------|--------|
| 모달 | `--paper`, 2px 테두리, `--shadow-lg`, 패딩 28px, radius 0. 백드롭 `rgba(21,21,21,0.55)` — 블러 없음 |
| 드롭다운 | 2px 테두리, `--shadow`, 항목 hover 배경 `--paper-sunken` |
| 토스트 | 하단 중앙, `--ink` 배경 + `--paper` 글자, 2px 테두리, `--shadow`, 4초 자동 닫힘 |

### Icons
- **아이콘보다 도형이 먼저다.** 원·삼각형·사각형·지그재그를 2px 검정 stroke로 직접 그린다. 크기 20/24/32px
- 실제 아이콘 세트가 필요하면 Lucide를 쓰되 **stroke를 2px로 올리고**, 반드시 2px 테두리 도형 안에 넣는다
- filled 아이콘·이모지 금지

## 5. Feedback Patterns (로딩 · 빈 화면 · 오류)

### Loading
- 1초 미만 예상 → 아무것도 표시하지 않음
- 영역 로딩 = 스켈레톤: `--paper-sunken` 면 + 2px 테두리, 콘텐츠와 같은 자리·크기. 투명도 1→0.6→1 을 1.4초 반복. **shimmer 금지**
- 버튼 로딩은 점 3개(`● ● ●`)가 순서대로 커지는 방식. 회전 스피너는 이 시스템의 형태 언어가 아니다
- 3초 이상 작업엔 진행 텍스트 병행

### Empty State
구성 순서 고정: ① 2px stroke 도형 픽토그램 56px ② 제목 22px/900 ③ 설명 14px `--ink-2` 1~2줄 ④ 버튼 1개. 중앙 정렬, 상하 패딩 72px+.
빈 화면은 밀도가 `full`이어도 패턴을 깔지 않는다 — 이미 비어 있는 화면을 더 시끄럽게 만들지 않는다.

### Error
- 폼 오류: 해당 입력창에 인라인
- 영역 오류: Empty State 구성 + "다시" Neutral 버튼
- 전체 페이지(404/500): 숫자를 Display 크기로 크게, 그 뒤에 도형 하나. 홈으로 가는 버튼 1개
- 오류 배너는 빨강 면 + 흰 글씨(`--on-red`). 빨강 글씨를 흰 배경에 쓰지 않는다

## 6. Patterns · Imagery · Charts

### 패턴 (이 시스템의 시그니처 — §1 `--z-pattern`)
네 가지만 쓴다. 전부 2px 검정 선, 단색, SVG.

| 이름 | 생김새 | 쓰는 곳 |
|------|--------|---------|
| Zigzag | 지그재그 선 | 섹션 구분, 히어로 하단 |
| Dots | 규칙적인 점 격자 | 넓은 여백 |
| Terrazzo | 불규칙한 색 반점 | 페이지 바닥 전체 |
| Squiggle | 물결 선 | 제목 밑줄, 강조 |

**규칙**
- 패턴은 `position: absolute` + `--z-pattern`으로 **콘텐츠 아래 레이어**에만 둔다
- **글자가 얹히는 면에는 절대 깔지 않는다.** 카드 배경, 표, 폼 뒤는 언제나 단색
- 한 화면에 패턴 2종까지. 밀도가 `half`·`quiet`면 0종
- 패턴 위에 도형을 겹치지 않는다

### 도형
- 원·삼각형·사각형·반원·지그재그만. 전부 2px 검정 테두리 + 팔레트 단색 채움
- **모든 도형은 테두리를 갖는다.** 다크 모드에서 테두리가 흰색으로 뒤집히므로, 채움색이 배경에 묻혀도 형태가 살아남는다
- 회전은 15° 단위로만. 아무 각도나 쓰지 않는다
- **밀도 `full`에서만 아주 느린 부유를 허용한다** — 주기 6초 이상, 이동 12px 이하, 회전 ±8° 이하. 본문 옆이 아니라 히어로·섹션 여백에만. 빠르게 움직이면 글을 못 읽는다
- 콘텐츠를 가리지 않는다 — 도형은 언제나 블록 모서리 바깥으로 절반쯤 빠져나간다

### 사진
- 2px 검정 테두리 + `--shadow`. radius 0
- 흑백 또는 단색 듀오톤(검정 + 팔레트 색 하나) 권장. 원본 컬러 사진은 팔레트와 싸운다
- 텍스트 오버레이 금지 — 사진 옆에 색 블록을 두고 거기에 글자를 넣는다

### 차트
- 색은 `--chart-1`~`--chart-6` 순서 고정. 막대·선·면 전부 **2px 검정 테두리**를 갖는다
- **색으로 구분이 어려우면 패턴 채우기(사선·점)를 쓴다.** 색맹 사용자에게도 구분되고, 멤피스의 형태 언어와도 맞는다
- 축 라벨 13px/700 `--ink-3` + `tabular-nums`. 그리드선은 2px 점선 `--ink-3`
- 막대 radius 0, 간격은 막대 폭의 40%+ / 파이·도넛: 5조각 이하
- 차트 카드 안에는 패턴을 깔지 않는다

## 7. Layout & Responsive (레이아웃 · 반응형)

### Spacing
- **4px 배수만**: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96
- 리듬: 블록 내부 16~24 / 블록 사이 24~32 / 섹션 사이 80~96 (모바일 48~64)
- 하드 섀도우가 오른쪽·아래로 4~6px 뻗으므로, **블록 사이 간격은 그림자 크기보다 최소 4배 크게** 잡는다. 안 그러면 그림자가 옆 블록을 침범한다

### Grid
- 최대 폭 `--container`(1160px), 본문 중심 페이지 720px. 좌우 여백: 데스크톱 32 / 모바일 20px
- **비대칭을 허용한다** — 2:1, 1:2 같은 불균등 분할이 멤피스답다. 단, 밀도 `quiet`에서는 균등 그리드만
- 카드 그리드: 3열 → 2열(tablet) → 1열(mobile), gap 24px

### Responsive
| 구간 | 폭 | 규칙 |
|------|-----|------|
| Mobile | <640px | 1열, 여백 20px, 섹션 간격 48px, 버튼 전체 폭 |
| Tablet | 640–1024px | 2열, 여백 24px |
| Desktop | ≥1024px | 3열, 최대 1160px, 여백 32px |

- 타이포 축소: Display 64→38 / H1 44→30 / H2 32→24 / Metric 40→30. **본문 16px은 모든 화면 유지**
- **모바일에서는 하드 섀도우를 3px로 줄인다.** 좁은 화면에서 4px 이상은 레이아웃을 밀어낸다
- 모바일에서 떠다니는 도형은 개수를 절반으로 줄인다 (밀도 `full`이어도)
- 터치 타깃 최소 44×44px

## 8. Motion · Voice · Accessibility

### Motion
**움직임의 양은 §2 장식 밀도를 따른다.** 모션 규칙을 화면마다 새로 정하지 않는다.

| 움직임 | full | half | quiet |
|--------|------|------|-------|
| 눌림(active) | ○ | ○ | ○ |
| 뜸(hover) + 오버슛 | ○ | ○ | ✕ |
| 카드 기울임 → 펴짐 | ○ | ✕ | ✕ |
| 도형 부유 | ○ | ✕ | ✕ |
| 모달·드롭다운 등장 | ○ | ○ | ○ |
| 스켈레톤 펄스 | ○ | ○ | ○ |

- 인터랙션(뜸·눌림·기울임)은 `--ease-pop`으로 살짝 지나쳤다 돌아온다. **퇴장과 페이드는 `--ease`로 딱 멈춘다** — 사라지는 것이 튕기면 산만하다
- 등장은 페이드만, `--dur-base`. 순차 등장(stagger)은 쓰지 않는다 — 콘텐츠가 늦게 뜬 것처럼 보인다
- **패턴은 어떤 밀도에서도 움직이지 않는다.** 배경이 흔들리면 글을 읽을 수 없다. 움직이는 것은 도형뿐이고, 그것도 `full`에서만
- 무한 반복은 도형 부유와 스켈레톤 펄스 둘뿐
- `prefers-reduced-motion` 시 전부 비활성화 — 부유와 기울임까지 포함해서

### Voice & Tone (UI 문구)
- **문장을 자르고 명사로 끝낸다.** "파일이 업로드되었습니다" ❌ → "파일 3개 업로드 완료" ⭕
- 버튼은 동사 한두 글자: "저장", "삭제", "보내기"
- 숫자를 앞세운다. "여러 개" 대신 "3개", "잠시 후" 대신 "10초"
- 감탄사·의성어 허용 — 이 시스템에서만. 단 화면당 한 번, 그리고 오류 문구에는 쓰지 않는다
- 이모지 금지. 표현이 필요하면 도형을 쓴다

### Accessibility
- 대비 AA: 본문 4.5:1, 24px+ 텍스트 3:1. §1의 모든 조합은 라이트·다크 양쪽에서 검증되었다
- **색 위의 글자색은 `--on-*` 로 고정되어 있다.** 임의로 바꾸면 시스템이 검증한 대비가 깨진다
- 색에만 의존 금지 — 뱃지에는 단어를, 차트에는 패턴 채우기를 병행한다
- 포커스는 테두리와 겹치지 않도록 **바깥쪽 오프셋 아웃라인**을 쓴다. 2px 테두리가 이미 있어서 안쪽 링은 보이지 않는다
- 패턴 레이어에는 `aria-hidden="true"`. 장식 도형도 마찬가지
- 검은고딕 제목은 자간이 좁으므로 24px 미만으로 쓰지 않는다 — 저시력 사용자에게 뭉쳐 보인다
- 페이지 `lang="ko"`

## 9. Quick Decision Rules (빠른 결정 규칙)

판단이 애매할 때 이 표 순서로 해결한다.

| 고민 | 답 |
|------|-----|
| 무엇부터 정하나 | **장식 밀도**(§2). full / half / quiet 중 하나를 먼저 고른다 |
| 색 | 이 블록에 색 하나를 배정 → 내부는 검정·흰색. 옆 블록과 같은 색은 피한다 |
| 색 위 글자색 | 고르지 않는다. `--on-*` 를 그대로 쓴다 |
| 팔레트 색으로 글씨를 쓰고 싶다 | 24px 이상 제목의 빨강·파랑만. 나머지는 전부 검정 |
| 폰트 | 제목 display, 본문 sans. 16px 이하에 검은고딕 금지 |
| 굵기 | 본문 400 / 강조·소제목 700 / 버튼·칩 900. 검은고딕은 굵기가 하나뿐 |
| 테두리 | 언제나 2px. 1px도 3px도 없다 |
| 그림자 | 하드 섀도우 3종 중 하나. 흐릿한 그림자는 존재하지 않는다 |
| 모서리 | 0. 칩·뱃지만 pill |
| 라벨 | 검정 칩 + 흰 글씨. 모노스페이스는 이 시스템에 없다 |
| 패턴을 깔고 싶다 | 글자가 얹히는 면인가? 그렇다면 깔지 않는다 |
| 삭제 버튼 | 빨강 아님. Neutral 버튼 + 확인 모달 |
| 차트 색 구분이 안 된다 | 색을 늘리지 말고 패턴 채우기를 쓴다 |
| 움직이고 싶다 | §8 표에서 지금 밀도의 열을 본다. 밀도가 정하지 내가 정하지 않는다 |
| hover를 어떻게 | 뜬다(그림자 커짐). 누를 때만 눌린다. 둘은 한 쌍 |
| 겹침 | §1 z-index 6단계 중 하나 — 새 값 발명 금지 |

### 자주 쓰는 조합 (복사용)
- **히어로**: `--canvas` 배경 + 패턴 1종, 검정 칩 라벨 → 제목 64px display/1.0 → 부제 18px/1.7 `--ink-2` → Primary + Quiet 버튼. 모서리 바깥으로 도형 2~3개
- **카드**: `--paper`, 2px 테두리, `--shadow`, 패딩 24px, 상단 8px 색 띠 → 칩 라벨 → 제목 22px/900 → 본문 16px/1.7 `--ink-2`
- **색 블록**: 팔레트 색 배경, 2px 테두리, `--shadow-lg`, 글자는 `--on-*`, 내부 칩은 흰 배경 검은 글씨
- **지표**: 칩 라벨 → 숫자 40px display → 증감 14px/700. 카드 전체 배경색은 쓰지 않고 상단 띠만
- **빈 화면**: 도형 픽토그램 56px + 제목 22px/900 + 설명 14px + 버튼 1개, 패턴 없음, 패딩 72px+
